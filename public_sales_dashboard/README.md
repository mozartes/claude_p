# 공공영업 통합 대시보드 (public_sales_dashboard)

공공고객담당 AM·팀장·영업관리자가 **담당 전체 / 팀 / AM** 단위로 ACR 매출, 수주 예정·경과 사업, 재계약 감액·해지 위험, 후속 확인 과제를 보는 Flask 대시보드입니다.
화면은 **KPI → 원인 → 해당 Funnel 목록 → 확인할 행동** 순서로 연결됩니다(카드·차트·표 클릭 → 상세 목록 → 원본 행).

- 저장소 위치: `claude_p/public_sales_dashboard/` (저장소 루트의 기존 Next.js 설문 앱과 별개 폴더, 기존 파일 미변경)
- 구성: Python · Flask · pandas/openpyxl · waitress · HTML/CSS/JS · Chart.js 4.4.1(로컬 포함)
- **외부 인터넷 없이 동작**(CDN·웹폰트·외부 API 없음), 회사 데이터를 외부 서비스로 전송하지 않음

## 2. 필요 환경

- Python 3.10 이상 (개발·테스트: Python 3.13, Flask 3.1, pandas 3.0, openpyxl 3.1, waitress 3.0)
- 패키지: `requirements.txt`

## 3. 설치·실행 (Windows PowerShell)

```powershell
cd claude_p\public_sales_dashboard
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
Copy-Item .env.example .env      # 필요 값 수정
python app.py                    # 개발 실행 → http://127.0.0.1:8000
```

운영 실행(Debug OFF, waitress):

```powershell
python serve.py
# 또는
waitress-serve --host 0.0.0.0 --port 8000 app:app
```

테스트:

```powershell
python -m pytest -q
```

## 4. 환경변수 (.env)

| 변수 | 기본값 | 설명 |
|---|---|---|
| HOST / PORT | 127.0.0.1 / 8000 | 바인딩 주소 |
| URL_PREFIX | (없음) | 예: `/public-acr`. 끝 슬래시·중복 슬래시는 자동 정리 |
| DATA_DIR | ./data | 원본·업로드 저장 경로(**영속 저장소로 지정 권장**) |
| LOG_DIR | ./logs | 로그 경로(`app.log`, 2MB×5 회전) |
| FLASK_DEBUG | 0 | 개발 실행(`python app.py`)에서만 의미, 운영(`serve.py`)은 항상 OFF |
| MAX_UPLOAD_MB | 20 | 업로드 최대 크기 |
| ADMIN_TOKEN | (없음) | 설정 시 업로드·적용에 토큰 필요(조회와 권한 분리). 미설정이면 화면에 경고 |
| DEFAULT_DATA_FILE | (없음) | 업로드 이력이 없을 때 시작 시 읽을 원본 경로 |
| BASE_DATE | (없음) | 기준일 고정(YYYY-MM-DD). 비우면 서버 오늘 날짜 |
| TARGET_HQ | 공공고객담당 | 기본 대상 본부 |
| SOURCE_UNIT | unknown | 원본 금액 단위(unknown·원·천원·백만원·억원) |
| STALE_DAYS | 30 | 미갱신 기준(일, 초과 시 미갱신) |
| LARGE_CONTRACT_AMOUNT | 1000 | 대형 A/C: 계약기간매출 ≥ 값(원본 단위) |
| LARGE_RENEWAL_MONTHLY | 30 | 대형 R: 기존 월매출 ≥ 값(원본 단위) |
| IMMINENT_MONTHS | 1 | 임박: 기준월~+N개월(1=이번 달·다음 달) |
| HIGH_PROBABILITY | 70 | 높은 입력 가능성(%) |

업무 기준값은 사이드바 ‘업무 기준값’에서 조회 시 바꿀 수 있고, 적용값은 화면 상단·확인 패널·다운로드 파일에 기록됩니다.
대형 기준 기본값(1000 / 30)은 실제 원본 분포(진행 중 A/C 계약기간매출 90분위 ≈ 1,637, R 기존매출 90분위 ≈ 30)를 참고한 **초기값**이며 업무 기준 확정이 필요합니다.

## 5. 엑셀 업로드·갱신

1. 메뉴 **데이터 관리** → 파일 선택 → **검증**
2. 시트(`유선Funnel조회` 우선, 없으면 필수 열이 있는 시트)·헤더 행(1~10행 탐색) 확인, 품질 미리보기
3. **적용** → 원본은 `DATA_DIR/raw/YYYYMMDD_HHMMSS_파일명.xlsx`로 그대로 보존, `DATA_DIR/current.json`이 현재본을 가리킴
4. 검증 실패(확장자·크기·손상·필수 열 누락) 시 기존 데이터 유지. 적용은 완성된 데이터셋으로 잠금 안에서 한 번에 교체되어 조회 중 사용자에게 불완전한 데이터가 보이지 않음

필수 열: 고객사, 수주년월, 월매출합계, 현재상황, 팀, AM, ACR유형, 계약기간(월), 매출발생년월, Funnel번호, 본부, 계약기간매출, 기존매출, 변경매출 (열 번호가 아닌 **헤더 이름**으로 연결).

## 6. 지표 정의와 기본 가정

**원본 분석 결과(첨부 파일 직접 재확인)**: 시트 `유선Funnel조회`, 헤더 1행, 데이터 1,104건, 80열(A~CB), 본부 전부 공공고객담당, Funnel번호 공백·중복 0건, 년월은 YYYYMM 정수, 저장일시는 `YYYY-MM-DD` 문자열. 품질 확인 행 14건(상품별 월매출 합계≠월매출합계 8, 계약기간 0 5, R 금액 관계 불일치 2).

| 구분 | 정의 |
|---|---|
| ACR 확정 | A=Acq.+Win, C=Cul.+Win, R=Ret.+재계약완료. Pre Sales·제안완료·Lose·Drop·해지확정 제외 |
| ① 매출개시월 기준(기본) | 적격 Funnel의 월매출합계를 **매출발생년월에 1회** 배치. 해당 월 시작 월매출 증감 규모(반복 청구·회계 실적 아님) |
| ② 계약기간 반영 추정 | 매출발생년월(포함)부터 계약기간(월) 동안 매월 반영, 종료 다음 달 제외, 일할 없음, 전년도 시작 계약도 기간 내 유효분 반영. **추정치** |
| R | 월매출합계 = 재계약 증감액(음수 유지). 재계약 후 월매출(변경매출)은 별도 지표이며 ACR 합계에 더하지 않음 |
| 합계 | A+C = A + C, A+C+R = A + C + R. 조직별 합계 = 담당 전체 |
| Funnel 건수 | 월별 반복 횟수가 아닌 고유 Funnel 수 |
| 진행 중 | Pre Sales·제안완료. 금액 = 원본 계약기간매출(누락 시 대체 안 함), 음수와 양수 상계 안 함 |
| 수주 예정월 | 진행 중 건의 수주년월을 예정월로 사용(**업무 가정**). 기준월보다 이전일 때만 ‘경과’ |
| 수주 가능성 | ‘50%(중중)’처럼 명시적 0~100% 값만 사용, 그 외 미확인. 가중 추정 = 계약기간매출 × 가능성(참고치, 원본 ‘수주가능매출’과 동일시 안 함) |
| 수주율 | 승패 결정 건 기준 = Win/(Win+Lose), Drop 분모 제외, 분모 0이면 산출 불가, 수주년월 기준 현재 종결상태 |
| 재계약 | 증액/동일/감액 = 월매출합계 부호. 증감률 = (변경 합 − 기존 합)/기존 합, 기존매출 양수 대상만(행 평균 아님) |
| 해지확정 | 수주년월 기준 집계, 해지월로 단정하지 않음, 확정 ACR 합계에서 제외 |
| 최근 갱신 | 최근영업활동내역 저장일시 기준(고객 접촉일·활동 횟수 아님). 미입력·기준일 이후 날짜는 별도 표시 |
| 중복 | Funnel번호 중복·공백 행은 검토 목록에 표시하고 해결 전 집계 제외(병합·삭제 안 함). 같은 입찰공고번호는 중복 아님 |
| 상품 | 상품1~5↔월매출1~5 짝 처리. 상품 선택 시 대응 월매출만 합산, Funnel 단위 금액은 고유 Funnel당 1회 |
| 고객 | 고객사 **표시명 기준**(마스킹 이름이 같아도 동일 고객 단정 안 함). 고유·신규 고객 수, 유지율 미산출 |
| 미산출 | 목표 달성률, 과거 단계 전환율·체류기간, 재계약 성공률·고객 유지율, 자동 성과등급, Commit·회계매출·Recur. (근거 데이터 없음) |
| 보조 필터 | 중대형퍼널제외·RMR제외·확정자 유무는 **기본 미적용**, 사이드바에서 선택 시 적용 표시 |

우선 확인 Funnel은 14개 조건 규칙(높음/중간/낮음)으로 정렬한 **업무 확인 순서**이며 수주 확률·AM 평가점수가 아닙니다. 한 Funnel의 여러 사유는 한 행에 모읍니다. 규칙 표는 각 화면 하단·다운로드 파일 ‘확인규칙’ 시트에 있습니다.

**금액 단위**: 원본 숫자만으로 단위를 확정하지 않아 기본은 ‘원본 단위·확인 필요’(변환 없음). 사이드바 ‘금액 단위’에서 원본 단위를 지정하면 원/천원/백만원/억원으로 변환 표시합니다. 계산 중 반올림 없음, 표시할 때만 반올림.

## 7. Playground 배포

첨부 화면 기준 ‘앱 유형: Python → 템플릿: Flask’를 선택합니다. 아래 항목은 이미지만으로 확인되지 않아 **확인이 필요**합니다.

| 항목 | 이 프로젝트의 대응 |
|---|---|
| Python 버전 | 3.10 이상이면 동작(3.13에서 검증) |
| 시작 명령 | `python serve.py` 권장. Flask 템플릿이 `app:app` 객체를 찾으면 `app.py`의 `app` 사용 가능 |
| 포트 | Playground가 지정하는 포트를 `PORT` 환경변수로 전달, `HOST=0.0.0.0` |
| WSGI | waitress(`waitress-serve app:app`) 또는 플랫폼 기본 WSGI 모두 가능 |
| 경로 접두어 | 하위 경로로 서비스되면 `URL_PREFIX=/public-acr` 등 지정 |
| 저장소 영속성 | 휘발성이면 재시작 시 업로드본이 사라짐 → `DATA_DIR`를 영속 볼륨으로 지정하거나 `DEFAULT_DATA_FILE` 사용 |
| 비밀 보관함 | `ADMIN_TOKEN`은 Playground ‘비밀 보관함’에 등록(코드·저장소에 기록 금지) |

배포 순서: ① 프로젝트 설정 → ② 비밀 보관함에 ADMIN_TOKEN 등 등록 → ③ Python/Flask 선택 → ④ 정보 입력(시작 명령·포트·환경변수) → 배포 후 `/healthz`(또는 `/public-acr/healthz`)로 확인 → 데이터 관리에서 엑셀 업로드.

## 8. URL_PREFIX

`PrefixMiddleware` 한 곳에서 처리합니다. 요청이 `/public-acr/...`로 오면 접두어를 SCRIPT_NAME으로 옮기고, 프록시가 접두어를 제거해 전달해도 링크는 접두어를 1회만 붙여 생성합니다. 템플릿은 `url_for`, JavaScript API 주소는 서버가 `data-api`로 전달합니다. CSS·JS·차트 라이브러리·API·업로드·다운로드·redirect를 접두어 없음과 `/public-acr` 모두에서 테스트했습니다.

## 9. 데이터 저장·보존, 업데이트

- `DATA_DIR/raw/`: 적용된 원본 전체 이력(삭제하지 않음, 필요 시 운영자가 보관 정책에 따라 정리)
- `DATA_DIR/current.json`: 현재 적용본 포인터(재시작 시 자동 로드)
- `DATA_DIR/staging/`: 검증만 하고 적용하지 않은 파일(6시간 후 자동 정리)
- 회사 원본·업로드본·`.env`·로그는 `.gitignore`로 저장소에서 제외
- 코드 업데이트: 저장소 pull → `pip install -r requirements.txt` → 재시작(데이터는 DATA_DIR에 유지)

## 10. 로그·오류 확인

- `LOG_DIR/app.log`: 업로드·검증·적용·화면 집계·다운로드의 처리 시간, 건수, 성공·실패, 오류 요약
- 고객명·영업활동 원문·인증정보는 기록하지 않음
- 화면 오류 메시지가 나오면 `app.log`의 `ERROR`/`Traceback` 확인

## 11. 보안·권한

- API Key·비밀번호·토큰 하드코딩 없음, `.env.example`은 예시값만 포함
- 사이드바 필터는 **조회 범위 선택이며 접근 권한 통제가 아님**
- 업로드·적용은 `ADMIN_TOKEN`으로 조회와 분리 가능
- **사내 인증(SSO 등) 연동은 적용하지 않음** — 방식이 확인되면 리버스 프록시 또는 Flask before_request 단계에 추가 필요

## 12. 확인이 필요한 사내 환경 조건

1. 원본 금액 단위(백만원 추정 가능하나 미확정) → 확정 후 `SOURCE_UNIT` 설정
2. 대형·임박·미갱신·높은 가능성 기준값 업무 확정
3. Playground Python 버전·시작 명령·포트·WSGI·저장소 영속성
4. 사내 인증 방식과 업로드 권한자 범위
5. ‘수주년월 = 진행 중 건의 예정월’ 가정, ‘수주가능매출’·‘수주예상금액’ 정의
6. 향후 개선: 나라장터 OpenAPI 연동(입찰 마감일 등), 고객 코드 연동(고유 고객 지표), 이력 스냅샷 축적(전환율·추이)
