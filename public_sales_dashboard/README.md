# 공공영업 통합 대시보드 (public_sales_dashboard)

공공고객담당 AM·팀장·영업관리자가 **담당 전체 / 팀 / AM** 단위로 ACR 수주, 수주 예정·경과 사업, 재계약 감액·해지 위험, 후속 확인 과제를 보는 Flask 대시보드입니다.
화면은 **KPI → 원인 → 해당 Funnel 목록 → 확인할 행동** 순서로 연결됩니다(카드·차트·표 클릭 → 상세 목록 → 원본 행).

- 저장소 위치: `claude_p/public_sales_dashboard/` (저장소 루트의 기존 Next.js 설문 앱과 별개 폴더, 기존 파일 미변경)
- 구성: Python · Flask · pandas/openpyxl · waitress · HTML/CSS/JS · Chart.js 4.4.1(로컬 포함)
- **외부 인터넷 없이 동작**(CDN·웹폰트·외부 API 없음), 회사 데이터를 외부 서비스로 전송하지 않음

## 2. 필요 환경

- Python 3.10 이상 (개발·테스트: Python 3.13, Flask 3.1, pandas 3.0, openpyxl 3.1, waitress 3.0)
- 패키지: `requirements.txt`

## 3. 설치·실행 (Windows PowerShell)

```powershell
cd claude_p\public_sales_dashboard
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
Copy-Item .env.example .env      # 필요 값 수정
python app.py                    # 개발 실행 → http://127.0.0.1:8000
```

운영 실행(Debug OFF, waitress):

```powershell
python serve.py
# 또는
waitress-serve --host 0.0.0.0 --port 8000 app:app
```

테스트:

```powershell
python -m pytest -q
```

## 4. 환경변수 (.env)

| 변수 | 기본값 | 설명 |
|---|---|---|
| HOST / PORT | 127.0.0.1 / 8000 | 바인딩 주소 |
| URL_PREFIX | (없음) | 예: `/public-acr`. 끝 슬래시·중복 슬래시는 자동 정리 |
| DATA_DIR | ./data | 원본·업로드 저장 경로(**영속 저장소로 지정 권장**) |
| LOG_DIR | ./logs | 로그 경로(`app.log`, 2MB×5 회전) |
| FLASK_DEBUG | 0 | 개발 실행(`python app.py`)에서만 의미, 운영(`serve.py`)은 항상 OFF |
| MAX_UPLOAD_MB | 20 | 업로드 최대 크기 |
| ADMIN_TOKEN | (없음) | 설정 시 업로드·적용에 토큰 필요(조회와 권한 분리). 미설정이면 화면에 경고 |
| DEFAULT_DATA_FILE | (없음) | 업로드 이력이 없을 때 시작 시 읽을 원본 경로 |
| BASE_DATE | (없음) | 기준일 고정(YYYY-MM-DD). 비우면 서버 오늘 날짜 |
| TARGET_HQ | 공공고객담당 | 기본 대상 본부 |
| LEASED_PRODUCTS | 국내전용,국제전용,국외전용 | 상품 카테고리 ‘전용회선’에 넣을 상품명(원본 표기는 국제전용) |
| SOURCE_UNIT | 백만원 | 원본 금액 단위(확인 완료: 백만원). unknown 으로 두면 변환 없이 ‘확인 필요’ 표시 |
| STALE_DAYS | 30 | 미갱신 기준(일, 초과 시 미갱신) |
| LARGE_CONTRACT_AMOUNT | 1000 | 대형 A/C: 계약기간매출 ≥ 값(백만원, 1000=10억원) |
| LARGE_RENEWAL_MONTHLY | 30 | 대형 R: 기존 월매출 ≥ 값(백만원, 30=월 3천만원) |
| IMMINENT_MONTHS | 1 | 임박: 기준월~+N개월(1=이번 달·다음 달) |
| HIGH_PROBABILITY | 70 | 높은 입력 가능성(%) |

업무 기준값은 사이드바 ‘업무 기준값’에서 조회 시 바꿀 수 있고, 적용값은 화면 상단·확인 패널·다운로드 파일에 기록됩니다.
대형 기준 기본값(1000 / 30)은 실제 원본 분포(진행 중 A/C 계약기간매출 90분위 ≈ 1,637, R 기존매출 90분위 ≈ 30)를 참고한 **초기값**이며 업무 기준 확정이 필요합니다.

## 5. 엑셀 업로드·갱신

1. 메뉴 **데이터 관리** → 파일 선택 → **검증**
2. 시트(`유선Funnel조회` 우선, 없으면 필수 열이 있는 시트)·헤더 행(1~10행 탐색) 확인, 품질 미리보기
3. **적용** → 원본은 `DATA_DIR/raw/YYYYMMDD_HHMMSS_파일명.xlsx`로 그대로 보존, `DATA_DIR/current.json`이 현재본을 가리킴
4. 검증 실패(확장자·크기·손상·필수 열 누락) 시 기존 데이터 유지. 적용은 완성된 데이터셋으로 잠금 안에서 한 번에 교체되어 조회 중 사용자에게 불완전한 데이터가 보이지 않음

필수 열: 고객사, 수주년월, 월매출합계, 현재상황, 팀, AM, ACR유형, 계약기간(월), 매출발생년월, Funnel번호, 본부, 계약기간매출, 기존매출, 변경매출 (열 번호가 아닌 **헤더 이름**으로 연결).

## 6. 지표 정의와 기본 가정

**원본 분석 결과(첨부 파일 직접 재확인)**: 금액 단위 백만원(확인 완료), 시트 `유선Funnel조회`, 헤더 1행, 데이터 1,104건, 80열(A~CB), 본부 전부 공공고객담당, Funnel번호 공백·중복 0건, 년월은 YYYYMM 정수, 저장일시는 `YYYY-MM-DD` 문자열. 품질 확인 행 14건(상품별 월매출 합계≠월매출합계 8, 계약기간 0 5, R 금액 관계 불일치 2).

| 구분 | 정의 |
|---|---|
| ACR 확정 | A=Acq.+Win, C=Cul.+Win, R=Ret.+재계약완료. Pre Sales·제안완료·Lose·Drop·해지확정 제외 |
| ① 매출개시월 기준(선택) | 적격 Funnel의 월매출합계를 **매출발생년월에 1회** 배치(신규 증분만 볼 때). 해당 월 시작 월매출 증감 규모(반복 청구·회계 실적 아님) |
| ② 계약기간 반영(**기본**, 2026-11 변경) | 매출발생년월(포함)부터 계약기간(월) 동안 매월 반영, 종료 다음 달 제외, 일할 없음, 전년도 시작 계약도 기간 내 유효분 반영. 예) 1월 개시 68.49 + 2월 개시 1.21 → 2월 69.70. 계약기간 누락·0인 확정 건은 제외 건수로 표시. 종합 현황·ACR 수주·팀·AM·상품·고객 집계가 모두 이 기준을 따름. **추정치** |
| R | **2026-11 변경:** R 금액 = 재계약 후 월매출(변경매출, 리텐션 매출). A+C+R = A+C 기여매출 + R매출(종합 현황·ACR 수주·팀·AM·월별 차트·고객 집계 공통). 증감액(변경−기존)은 종합 현황 R매출 카드의 ‘증감’과 R+해지 카드에 표시. 상품·카테고리 선택 시에는 변경매출을 상품별로 나눌 수 없어 R = 상품 슬롯 금액(증감) 유지. ACR 수주(계약기간) 화면은 기존대로 계약기간매출(증감×계약기간) |
| 합계 | A+C = A + C, A+C+R = A + C + R. 조직별 합계 = 담당 전체 |
| Funnel 건수 | 월별 반복 횟수가 아닌 고유 Funnel 수 |
| 진행 중 | Pre Sales·제안완료. 금액 = 원본 계약기간매출(누락 시 대체 안 함), 음수와 양수 상계 안 함 |
| 수주 예정월 | 진행 중 건의 수주년월을 예정월로 사용(**업무 가정**). 기준월보다 이전일 때만 ‘경과’ |
| 수주 가능성 | ‘50%(중중)’처럼 명시적 0~100% 값만 사용, 그 외 미확인. 가중 추정 = 계약기간매출 × 가능성(참고치, 원본 ‘수주가능매출’과 동일시 안 함) |
| 수주율 | 승패 결정 건 기준 = Win/(Win+Lose), Drop 분모 제외, 분모 0이면 산출 불가, 수주년월 기준 현재 종결상태 |
| 재계약 | 증액/동일/감액 = 월매출합계 부호. 증감률 = (변경 합 − 기존 합)/기존 합, 기존매출 양수 대상만(행 평균 아님) |
| 해지확정 | 수주년월 기준 집계, 해지월로 단정하지 않음, 확정 ACR 합계에서 제외 |
| 최근 갱신 | 최근영업활동내역 저장일시 기준(고객 접촉일·활동 횟수 아님). 미입력·기준일 이후 날짜는 별도 표시 |
| 중복 | Funnel번호 중복·공백 행은 검토 목록에 표시하고 해결 전 집계 제외(병합·삭제 안 함). 같은 입찰공고번호는 중복 아님 |
| 상품 | 상품1~5↔월매출1~5 짝 처리. 상품 선택 시 대응 월매출만 합산, Funnel 단위 금액은 고유 Funnel당 1회 |
| 고객 | 고객사 **표시명 기준**(마스킹 이름이 같아도 동일 고객 단정 안 함). 고유·신규 고객 수, 유지율 미산출 |
| 미산출 | 목표 달성률, 과거 단계 전환율·체류기간, 재계약 성공률·고객 유지율, 자동 성과등급, Commit·회계매출·Recur. (근거 데이터 없음) |
| 보조 필터 | 중대형퍼널제외·RMR제외·확정자 유무는 **기본 미적용**, 사이드바에서 선택 시 적용 표시 |

우선 확인 Funnel은 14개 조건 규칙(높음/중간/낮음)으로 정렬한 **업무 확인 순서**이며 수주 확률·AM 평가점수가 아닙니다. 한 Funnel의 여러 사유는 한 행에 모읍니다. 규칙 표는 각 화면 하단·다운로드 파일 ‘확인규칙’ 시트에 있습니다.

**금액 단위**: 원본 금액 단위는 **백만원으로 확인**되어 `SOURCE_UNIT=백만원`이 기본값입니다(서버 설정이 화면 설정보다 우선, 화면에서는 원본 단위 변경 불가). 사이드바 ‘금액 단위’에서 표시 단위만 원/천원/백만원/억원 중 선택합니다(기본 백만원). 다운로드 파일은 원본 값(백만원) 그대로 기록합니다. 계산 중 반올림 없음, 표시할 때만 반올림.

## 7. Playground 배포

첨부 화면 기준 ‘앱 유형: Python → 템플릿: Flask’를 선택합니다. 아래 항목은 이미지만으로 확인되지 않아 **확인이 필요**합니다.

| 항목 | 이 프로젝트의 대응 |
|---|---|
| Python 버전 | 3.10 이상이면 동작(3.13에서 검증) |
| 시작 명령 | `python serve.py` 권장. Flask 템플릿이 `app:app` 객체를 찾으면 `app.py`의 `app` 사용 가능 |
| 포트 | Playground가 지정하는 포트를 `PORT` 환경변수로 전달, `HOST=0.0.0.0` |
| WSGI | waitress(`waitress-serve app:app`) 또는 플랫폼 기본 WSGI 모두 가능 |
| 경로 접두어 | 하위 경로로 서비스되면 `URL_PREFIX=/public-acr` 등 지정 |
| 저장소 영속성 | 휘발성이면 재시작 시 업로드본이 사라짐 → `DATA_DIR`를 영속 볼륨으로 지정하거나 `DEFAULT_DATA_FILE` 사용 |
| 비밀 보관함 | `ADMIN_TOKEN`은 Playground ‘비밀 보관함’에 등록(코드·저장소에 기록 금지) |

배포 순서: ① 프로젝트 설정 → ② 비밀 보관함에 ADMIN_TOKEN 등 등록 → ③ Python/Flask 선택 → ④ 정보 입력(시작 명령·포트·환경변수) → 배포 후 `/healthz`(또는 `/public-acr/healthz`)로 확인 → 데이터 관리에서 엑셀 업로드.

## 8. URL_PREFIX

`PrefixMiddleware` 한 곳에서 처리합니다. 요청이 `/public-acr/...`로 오면 접두어를 SCRIPT_NAME으로 옮기고, 프록시가 접두어를 제거해 전달해도 링크는 접두어를 1회만 붙여 생성합니다. 템플릿은 `url_for`, JavaScript API 주소는 서버가 `data-api`로 전달합니다. CSS·JS·차트 라이브러리·API·업로드·다운로드·redirect를 접두어 없음과 `/public-acr` 모두에서 테스트했습니다.

## 9. 데이터 저장·보존, 업데이트

- `DATA_DIR/raw/`: 적용된 원본 전체 이력(삭제하지 않음, 필요 시 운영자가 보관 정책에 따라 정리)
- `DATA_DIR/current.json`: 현재 적용본 포인터(재시작 시 자동 로드)
- `DATA_DIR/staging/`: 검증만 하고 적용하지 않은 파일(6시간 후 자동 정리)
- 회사 원본·업로드본·`.env`·로그는 `.gitignore`로 저장소에서 제외
- 코드 업데이트: 저장소 pull → `pip install -r requirements.txt` → 재시작(데이터는 DATA_DIR에 유지)

## 10. 로그·오류 확인

- `LOG_DIR/app.log`: 업로드·검증·적용·화면 집계·다운로드의 처리 시간, 건수, 성공·실패, 오류 요약
- 고객명·영업활동 원문·인증정보는 기록하지 않음
- 화면 오류 메시지가 나오면 `app.log`의 `ERROR`/`Traceback` 확인

## 11. 보안·권한

- API Key·비밀번호·토큰 하드코딩 없음, `.env.example`은 예시값만 포함

- 기여매출 = 조회기간 확정 ACR 월매출 증감액 합계(카드 아래에 기준·기간 표기)
- **R매출(리텐션)**(종합 현황, 2026-11 추가): 재계약완료 건의 **재계약 후 월매출(변경매출)**을 ACR 기준(매출발생년월·계약기간)으로 반영한 합계 = 재계약으로 확보한 매출 전체. 카드에 기존매출 유지분과 증감(= R 기여매출)을 함께 표시. A+C+R 기여매출 = A+C 기여매출 + R매출(리텐션)(2026-11 변경, 전 화면 공통). 상품·카테고리 선택 시에는 변경매출을 상품별로 나눌 수 없어 산출하지 않음
- 종합 현황 ACR(기여매출) 줄(R 기여매출 다음)과 ACR 수주(기여매출) 화면에 **R. 증감매출**(재계약 증감 + 해지 감소, R. 기여매출 다음 칸) 표시(2026-11)
- **R+해지 기여매출**(종합 현황, 2026-11 추가): R 기여매출(재계약완료 증감) + 해지확정 감소액. 해지확정의 월매출합계(= −기존매출)를 R과 같은 ACR 기준(매출발생년월·계약기간·상품 선택)으로 반영하며, 계약기간 누락 등은 계산 제외 건수로 표시. R 기여매출과 A+C+R 기여매출에는 해지를 넣지 않음(재계약 성과와 해지 손실 구분)
- 데이터 품질: 고객사 값이 90% 이상 한 가지로 입력된 경우 ‘원본 확인 필요’ 경고(엑셀 채우기 오류 의심, 원본은 수정하지 않음)

## 16. ACR 수주(Pre-sales)

진행 중(현재상황 Pre Sales·제안완료) Funnel의 예상 ACR 월매출을 **A / C / R 탭**별로 보여줍니다.

- 기간: 매출발생년월이 조회기간 안인 건(미입력·기간 밖은 제외 건수로 표시)
- 금액: 월매출합계(상품 선택 시 해당 상품 월매출) = 수주 시 예상 ACR 월매출 증감액. R은 재계약 증감(음수 유지)이며 기존·변경 월매출을 함께 표시
- 수주(재계약) 가능성 구간: 30%이하(0~29%) · 30%이상(30~39%) · 40%이상 · 50%이상 · 60%이상 · 70%이상 · 80%이상 · 90%이상(90~99%) · 100%이상(100%) · 미확인
- ‘해당 % 이상 누적’ 건수·월매출을 함께 표시(예: 70%이상 누적 = 70~100%)
- 가중 추정 = 월매출 × 가능성(참고치). 확정 ACR(기여매출)과 합산하지 않음
- 화면 맨 위 **월별 ACR 수주 증감액(Pre-sales)**: 매출발생년월별 예상 월매출을 가능성 5개 묶음(30%이하=0~29%, 30%이상=30~49%, 50%이상=50~69%, 70%이상=70~89%, 90%이상=90~100%) 막대 + 합계 선으로 표시. A+C+R / A / C / R 전환, 범례로 묶음 켜고 끄기, 막대 클릭 → 해당 월·구간 Funnel. 가능성 미확인 금액은 차트에서 제외(설명에 금액 표기)

## 17. ACR 수주(2026년) — 구 ACR 수주(계약기간), 메뉴·제목 연도는 집계연도에 따라 바뀜

확정 건의 **계약 전체 기간 매출(계약기간매출)**을 **수주년월**에 합산합니다. 기본 집계연도는 기준일 연도(1~12월)이며 화면 상단에서 연도를 바꿀 수 있습니다(사이드바 조회기간과 별개).

| 유형 | 대상 | 금액 |
|---|---|---|
| A | Acq. + Win | 계약기간매출 (= 월매출합계 × 계약기간) |
| C | Cul. + Win | 계약기간매출 |
| R | Ret. + 재계약완료 | **변경매출 × 계약기간**(리텐션 계약기간 매출, 2026-11 변경). 상품 선택 시는 상품 슬롯 금액(증감) × 계약기간 |

- 카드명: A. 수주 / C. 수주 / R. 재계약 / 2026년 수주(A+C) / A+C+R. 매출 (모두 수주년월 기준 계약기간매출 합계, A+C+R = A+C + R매출)
- R 참고 표: 기존 계약총액(기존매출×계약기간), 재계약 후 계약총액(= R. 매출), 증감(재계약 후 − 기존). 증액·동일·감액 건수와 조직별 R 감액 건수는 증감 기준으로 판정. 변경매출 또는 계약기간이 없는 R은 제외 건수로 표시합니다.
- 상품·카테고리를 선택하면 선택 상품 월매출 × 계약기간으로 계산합니다.
- 계약기간매출 누락 건은 제외 건수로 표시하고, 계약기간매출 ≠ 월매출합계×계약기간인 건은 원본 값 그대로 합산하며 건수를 표시합니다.

## 22. 기간 단위(월·분기·반기·연간)와 증감률(2026-11)

종합 현황 ② 추이, ACR 수주, ACR 수주(연도) 화면의 차트·표에 **월별 / 분기 / 반기 / 연간** 단위를 추가했습니다(선택은 브라우저에 저장). 기간별 표는 A+C·A+C+R마다 **직전 기간 대비(MoM·QoQ·HoH)와 전년동기 YoY를 함께** 표시합니다(연간은 YoY 하나).

- 계산: 화면이 이미 계산한 월별 값을 기간으로 묶어 더하기만 합니다(원 계산 로직 변경 없음).
- 증감률 = (이번 기간 − 비교 기간) ÷ 비교 기간. 표기: MoM·QoQ·HoH(직전 기간), YoY(전년 동기·연간).
- "—" 표시: 비교 기간 자료 없음, 비교 값 0 이하, 조회기간이 기간 일부만 포함("(일부)"), 기준월 이후 달이 섞인 진행 중 기간("(진행 중)", ACR 수주(연도)).
- ACR 수주(연도)의 전년 동기 값은 같은 화면 계산을 직전 연도로 한 번 더 조회해 씁니다. 현재 원본에는 2025년 수주 자료가 없어 YoY는 "—"입니다.
- 고유 Funnel 건수는 월을 합치면 중복되므로 기여매출 화면에서는 월별에서만 표시합니다(수주 화면 건수는 수주월 1회라 합산).
- 분기·반기·연간 보기에서는 차트·행 클릭으로 목록을 열지 않습니다(월별에서 사용).

## 24. A+C+R 기여매출 산식 변경(2026-11)

- 종합 현황 ACR(기여매출) 줄과 ACR 수주(기여매출) 화면의 **A+C+R 기여매출 = A 기여매출 + C 기여매출 + R. 증감매출**(재계약 증감 + 해지 감소).
- R 기여매출(재계약 후 월매출, 리텐션)은 참고용 카드로 남기고 이 합계에는 넣지 않음.
- 카드 표시값만 바뀜. 월별·기간별 차트·표, 팀·AM 표, ACR 수주(연도)의 A+C+R은 기존 기준(A+C + R 재계약 후 매출) 그대로.
- ACR 수주(연도) 화면 **R. 증감매출**(2026-11): 재계약 증감 × 계약기간(재계약 후 계약총액 − 기존 계약총액) + 해지확정(수주년월이 집계연도) 월매출합계(= −기존매출) × 계약기간. 계약기간 없는 해지 건은 계산 제외. A+C+R 합계와 별도.
- ACR 수주(연도) 화면과 종합 현황 1줄 **A+C+R = A + C + R. 증감매출**(재계약 증감 × 계약기간 + 해지 감소 × 계약기간). R. 재계약(변경매출 × 계약기간)은 참고용으로 합계 미포함. 종합 현황 1줄에도 R. 증감매출 카드 추가(2026-11).

## 25. A+C+R 통일 산식·R 용어 정리·Pre-sales 4색(2026-11)

- **A+C+R = A + C + R 증감** — 카드, 월별·기간별 차트·표, 조직별 표, 팀·AM 표, 상품·고객 집계 모두 같은 값.
  - 기여매출(조회기간 반영): R 증감 = 재계약 R 행의 월매출 증감 + 해지확정 감소액(같은 ACR 기준), 계산 엔진 필드 `RC`, A+C+R = `ACRN`.
  - 수주(연도, 계약기간): R 증감 = 재계약 증감 × 계약기간 + 해지 감소 × 계약기간(수주년월 기준).
  - 기존 필드 `R`(재계약 후 매출), `ACR`(A+C+R 재계약 기준)은 참고용으로 유지.
- **R 용어 3개**: R 재계약(재계약 후 확보 매출, 합계 미포함) · R 증감(재계약 증감 + 해지 감소) · 해지 감소.
- **Pre-sales 가능성 구간 4색**(주황 제외): 30%이하 적 · 30~69% 노랑 · 70~89% 파랑 · 90~100% 녹색. 인접 색 색약 검증 통과(적↔녹 같은 비인접 쌍은 축 라벨로 보완).
- 다크 테마 A·C·R 색을 검증 범위(밝기 0.48~0.67) 안으로 조정.

## 34. 기여매출 구성: 신규 발생 + Recurring (2026-11)

- 종합 현황 ‘ACR 기여매출’, ACR 수주(기여매출) 요약 아래에 한 줄 추가: **신규 발생(첫 달)** · **Recurring(둘째 달부터)** (비중) — Recurring A · C · R 증감.
- 신규 발생 = 조회기간에 매출이 시작된 계약의 첫 달 매출(매출개시월 기준 같은 계산), Recurring = A+C+R 기여매출(계약기간 반영) − 신규 발생. 두 값의 합 = 카드 합계.

## 47. ACR 수주(기여매출): R. 발생매출 · A+C+R. 발생매출 (2026-11)
- **R. 발생매출** = 재계약완료 건의 재계약 후 월매출(변경매출)을 기여매출과 같은 규칙(매출발생년월·계약기간)으로 반영한 금액. 재계약 때 줄어든 금액이 반영된 실제 매출(증감 아님). 카드에 재계약 전 금액과 재계약 감소·증가(= R. 증감 카드의 재계약 행)를 함께 표시합니다.
- **A+C+R. 발생매출** = A+C 기여매출 + R. 발생매출. 해지확정 건은 재계약 후 매출이 없어 포함되지 않습니다.
- 상품을 개별 선택하거나 상품 카테고리를 고르면 변경매출이 상품별로 없어 ‘자료 없음’으로 표시합니다. 기존 ‘참고 · R 재계약’ 줄은 이 카드로 대체했습니다.
- (v109) 발생매출 카드 2장을 작은 카드로 줄였습니다(섹션 폭 약 1/3). 종합 현황의 ACR 기여매출 섹션에도 같은 발생매출 카드를 넣고 ‘참고 · R 재계약’ 줄을 대체했습니다.
- (v110) 종합 현황 ‘ACR 수주(2026년) 목표 달성’ 표에서 ‘목표(억원)’ 입력 열을 삭제했습니다. 목표는 기본값 또는 ‘목표 엑셀 불러오기’로 정합니다.

## 48. 내장 기준 데이터 교체: 2021~2026 수주 통합 파일, 이름 마스킹 (2026-11)
- 웹판·메일판(기준데이터포함)의 내장 기준 데이터를 2021~2026 수주 통합 파일(6개 시트, 5,730건)로 바꿨습니다. 내장 데이터 파일(web_artifact/base_data.js)과 원본·마스킹 엑셀은 저장소에 올리지 않습니다.
